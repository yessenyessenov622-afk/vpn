# Telegram-бот: первый этап

Бот отвечает на `/start`, `/help` и `/language`. Кнопка «🌐 Язык» открывает выбор из восьми языков. Выбор сохраняется отдельно для каждого пользователя, в том числе после перезапуска. При первом обращении используется поддерживаемый язык Telegram, иначе русский. Кнопка «🆘 Техподдержка» позволяет отправить текстовое обращение администратору и получить ответ. Кнопка «👤 Моя подписка» показывает тестовую подписку, которую вручную выдаёт администратор. В разделе «💎 Тарифы» можно ознакомиться с будущими вариантами. Платежи и VPN-доступ не подключены.

## Как устроен проект

- `src/` — бот на TypeScript, кнопки и переводы (`src/translations.ts`).
- `storage/service.py` — Python-процесс для работы с пользователями, языками и тестовыми подписками; `app/database.py` работает с SQLite. Данные находятся в существующем `users.sqlite3`. Удалять его при перезапуске не нужно.
- TypeScript автоматически запускает Python и обменивается с ним короткими JSON-сообщениями через стандартный ввод и вывод. Открывать сетевой порт, запускать веб-сервер или отдельно запускать Python для работы бота не нужно. Боту и Python нужна одна папка проекта на одном компьютере или сервере.
- `java/SubscriptionFoundation.java` — отдельная заготовка. Бот её пока не использует, и она не представляет действующую подписку.
- Старые `bot.py`, `app/main.py`, `app/auth.py`, `static/` и `tests/test_app.py` сохранены для будущего возврата к Mini App. Не запускайте старый бот одновременно с новым: два процесса с одним токеном мешают друг другу. Старый `python bot.py` по-прежнему запускает прежнего Python-бота с Mini App, а не новую версию.

## 1. Что установить

Установите [Node.js LTS](https://nodejs.org/) (в него входит npm), [Python 3.10 или новее](https://www.python.org/downloads/) и [JDK](https://adoptium.net/temurin/releases/) (например, версию 17 или 21). При установке Python включите добавление в PATH; для JDK включите настройку PATH, если установщик её предлагает. После установки перезапустите VS Code и проверьте в терминале PowerShell:

```powershell
node --version
npm --version
python --version
java -version
javac -version
```

Если `javac` не найден, установленная Java может быть только средой запуска (JRE). Установите JDK и убедитесь, что папка `bin` JDK есть в PATH.

## 2. Подготовка и токен

Откройте папку проекта в VS Code и создайте терминал PowerShell. Если окружения `.venv` ещё нет, создайте его; если уже есть — повторно создавать не нужно:

```powershell
python -m venv .venv
```

Активируйте окружение и установите зависимости Node.js:

```powershell
.\.venv\Scripts\Activate.ps1
npm install
```

Для новой Python-части дополнительные пакеты не нужны: SQLite входит в Python. Старый `requirements.txt` оставлен для прежнего Mini App.

Если PowerShell не разрешает активацию, в текущем окне выполните `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` и повторите команду активации.

Создайте бота через [@BotFather](https://t.me/BotFather) командой `/newbot`. Если файла `.env` ещё нет, создайте его из шаблона:

```powershell
Copy-Item .env.example .env
```

Если `.env` уже существует, не копируйте шаблон поверх него. Откройте `.env` в VS Code и самостоятельно вставьте токен после `BOT_TOKEN=`. Не отправляйте токен в чат. `MINI_APP_URL` для нового бота не нужен. Если токен оказался доступен другим, отзовите его через BotFather и укажите новый в `.env`.

Добавьте в тот же `.env` строку `ADMIN_ID=123456789`, заменив пример на **свой** числовой Telegram ID. Это число, а не имя вида `@username`. Если строки нет, добавьте её с новой строки, не меняя остальные настройки.

Узнать ID можно через стороннего Telegram-бота [@userinfobot](https://t.me/userinfobot): откройте его, нажмите Start и найдите число ID в ответе. Это независимый сервис, которому будет видна ваша обычная информация профиля Telegram; не отправляйте ему токен или пароли. Бот поддержки должен запускаться с положительным числовым `ADMIN_ID`.

## 3. Запуск и остановка

В том же терминале, в папке проекта и с активным `.venv`, запустите:

```powershell
npm run build
npm start
```

При запуске бота Python-процесс стартует автоматически. Для отдельной проверки Python и доступности базы до запуска бота можно выполнить:

```powershell
python storage/service.py --check
```

Откройте личный чат с ботом в Telegram. Отправьте `/start`, нажмите «🌐 Язык», выберите язык и проверьте `/help` и `/language`. Остановите бота сочетанием `Ctrl+C`, запустите `npm start` снова и убедитесь, что язык сохранился. Для проверки отдельных настроек повторите с другим аккаунтом. Для выхода из окружения выполните `deactivate`.

Пока бот остановлен, он не отвечает. Интернет нужен для подключения к Telegram; публичный адрес и HTTPS-туннель для этого этапа не требуются.

## Как проверить техподдержку

1. После настройки `ADMIN_ID` запустите бота и войдите в его личный чат с аккаунта администратора. Нажмите `/start`. Telegram не позволяет боту первым начать личный разговор: без этого шага он не сможет доставить администратору обращение.
2. Для полной проверки откройте бота со второго аккаунта, нажмите `/start` и «🆘 Техподдержка». Напишите одну текстовую проблему длиной до 3000 символов. Если второй аккаунт недоступен, можно проверить отправку самому себе, но для проверки раздельной доставки нужны два аккаунта.
3. Убедитесь, что администратор получил текст, ID, имя и дату. Под обращением нажмите «Ответить», напишите ответ и проверьте, что пользователь его получил. Администратор увидит подтверждение только после отправки.
4. Проверьте «Отмена» для пользователя и администратора, отправьте фотографию вместо текста и слишком длинный текст. Затем отправьте обращения с двух разных аккаунтов: выберите сначала одно, потом другое и убедитесь, что бот сообщил о переключении и ответ пришёл второму пользователю.
5. Для проверки ошибки доставки можно временно заблокировать бота на принимающем аккаунте, выполнить отправку и убедиться, что отправитель увидел ошибку. После проверки разблокируйте бота и снова нажмите `/start`.

Для обращения и ответа поддерживается только текст, до 3000 символов. Отмена и команды `/start`, `/help`, `/language` завершают текущий режим ввода. Незавершённый ввод хранится только в памяти: после перезапуска бота его нужно начать заново. Уже доставленные сообщения остаются в чате; администратор может снова нажать «Ответить» на них. История обращений в SQLite не записывается, существующие настройки языка не меняются.

## Тестовая подписка

Пользователь сначала открывает личный чат с ботом и отправляет `/start`. Получить свой числовой ID пользователь может через стороннего [@userinfobot](https://t.me/userinfobot), а затем сообщить это число администратору. Аккаунт администратора в личном чате с ботом отправляет команду:

```text
/grant_test 123456789 7
```

Замените `123456789` на ID тестового пользователя, а `7` — на нужное число дней от 1 до 365. Если бот не знает пользователя, он попросит его сначала отправить `/start`. При первом запуске новой версии люди, ранее вручную сохранившие язык, автоматически учитываются как зарегистрированные. Ранее открывшие бота, но не сохранившие язык, могли не попасть в старую базу — им нужно открыть бота заново.

Активная тестовая подписка продлевается от даты окончания; истёкшая начинается заново. В «👤 Моя подписка» видны статус, начало, окончание и оставшееся время. Даты и расчёты используют UTC. Истечение определяется при просмотре, в том числе после перезапуска. Это тестовая запись: она не подтверждает оплату и не даёт VPN-доступа.

При первом запуске Python добавляет в существующую базу таблицы `registered_users` и `test_subscriptions`, если их нет, и переносит ID из существующих языковых настроек. Данные и таблица языков не удаляются; повторный запуск безопасен.

Чтобы проверить истечение без ожидания дней и без изменения настоящей базы, выполните:

```powershell
npm test
python -m unittest discover -s tests -p test_storage_service.py -v
```

Тесты используют временную базу и условное время: проверяют момент окончания, повторную выдачу после истечения и отображение статуса. Это автоматическая проверка; реальное истечение в Telegram она не имитирует.

## Локальные правила будущего VPN

`app/vpn_policy.py` определяет, нужно ли разрешить или отозвать доступ подготовленного устройства по сроку подписки. Он не подключён к боту и не управляет настоящим VPN. Время задаётся в Unix-секундах UTC, как и в SQLite; для проверок можно передать условное время. Ровно в момент окончания подписка считается истёкшей.

Сначала правило возвращает требуемое действие. Затем отдельная функция может передать его явно указанному контроллеру. Состояние устройства меняется в результате только после явного подтверждения контроллера; при ошибке сохраняется последнее подтверждённое состояние. После ошибки фактическое состояние сервера может быть неизвестно: будущему реальному контроллеру потребуется сверка и безопасное повторение. Перед реальным применением нужно повторно проверить актуальную подписку, поскольку после расчёта решения она могла измениться.

Пока контроллер имитируется только в тестах. Если последнее состояние устройства неизвестно или при последней операции произошла ошибка, правило требует сначала проверить фактическое состояние сервера. Проверка использует временные данные и временную SQLite:

```powershell
python -m unittest discover -s tests -p test_vpn_policy.py -v
```

## Подготовка хранения VPN-устройств

При следующем запуске Python создаст в существующей базе таблицу `vpn_devices`, если её ещё нет. Существующие пользователи, языки и подписки сохраняются. Таблица хранит не более одного устройства на Telegram ID: публичный ключ, время создания и обновления в UTC, последнее подтверждённое состояние (`unknown`, `allowed` или `revoked`) и код последней ошибки. Один публичный ключ нельзя назначить двум пользователям.

Функции находятся в `app/vpn_devices.py`; к Telegram-боту они пока не подключены. Новый ключ проверяется как канонический Base64 длиной 32 байта. Формат сам по себе не позволяет отличить публичный ключ от закрытого: при будущей интеграции нужно передавать только публичный ключ. Закрытые ключи здесь не создаются.

Новое устройство получает состояние `unknown`. Функция записи подтверждённого состояния предназначена для доверенного кода после ответа контроллера; её параметр подтверждения сам по себе не проверяет сервер. Реального контроллера пока нет. Ошибки записываются ограниченным набором кодов (`connection_error`, `controller_rejected`, `confirmation_lost`, `internal_error`), чтобы не сохранять случайные секреты из текстов исключений. Ошибка не меняет последнее подтверждённое состояние, но до повторной сверки с сервером оно может отличаться от фактического.

Проверки миграции и хранения работают на временной базе:

```powershell
python -m unittest discover -s tests -p test_vpn_devices.py -v
```

## Подготовка подключения VPN в боте

Кнопка «🔑 Подключить VPN» проверяет подписку и просит только публичный ключ WireGuard. До настройки отдельного ограниченного контроллера сервером бот ответит, что управление VPN недоступно: он не использует административный доступ AWS и не показывает неподтверждённые параметры. При отсутствии или истечении подписки запрос отклоняется. Отмена возвращает в меню.

`app/vpn_provision.py` содержит подготовленную логику проверки подписки, выделения адреса и подтверждения через интерфейс контроллера. Контроллер пока существует только как имитация в тестах. При следующем запуске новая миграция добавит к `vpn_devices` столбцы `vpn_ip` и `server_id` и уникальный индекс адресов; прежние записи сохраняются. Текущий тестовый peer, добавленный вручную на сервер, не присваивается пользователю автоматически только на основании публичного ключа.

Перед настоящей выдачей нужно создать и проверить отдельный механизм управления первым сервером с минимальными правами и ограниченными операциями. Актуальный публичный адрес должен получаться от этого механизма, а не из сохранённого ранее значения. Нужны атомарная проверка и сохранение peer на сервере, обработка неоднозначного результата и проверка срока подписки на границе выдачи. До этого реальный сценарий через бота не работает; существующий вручную подключённый Android-peer не изменяется. Автоматический отзыв по окончании подписки пока отсутствует, поэтому система не готова для платных клиентов.

Не отправляйте закрытый ключ в бот. Публичный и закрытый ключи имеют одинаковый формат, поэтому проверка Base64 не может надёжно различить их. Пока реализован только IPv4; IPv6 может идти напрямую.

Локальные проверки с временной базой и имитацией сервера:

```powershell
python -m unittest discover -s tests -p test_vpn_provision.py -v
npm test
```

## Ознакомительные тарифы

В главном меню нажмите «💎 Тарифы» и выберите 1, 3 или 6 месяцев. В описании доступны кнопки возврата к списку и в главное меню. Цены и оплата появятся позже; просмотр тарифа не меняет тестовую подписку. Длительность и названия тарифов находятся в `src/plans.ts`, а остальные тексты раздела — в `src/plan-translations.ts`.

## 4. Проверка Java отдельно

После установки JDK в PowerShell выполните:

```powershell
New-Item -ItemType Directory -Force java\build | Out-Null
javac -d java\build java\SubscriptionFoundation.java
java -cp java\build SubscriptionFoundation
```

Должно появиться сообщение `Subscription foundation is ready for future development.` Java не требуется для запуска бота на этом этапе.

## 5. Автоматические проверки и ошибки

```powershell
npm test
python -m unittest discover -s tests -p test_storage_service.py -v
```

`npm test` собирает TypeScript и проверяет переводы, команды, поддержку, тарифы и подписки на имитациях Telegram без настоящих сообщений, а также связь TypeScript и Python с временной SQLite. Python-тест отдельно проверяет миграцию, сохранение после перезапуска, продление и истечение на временной базе.

- Если бот сообщает об отсутствии токена, проверьте `.env` и запустите его из папки проекта. Если не может подключиться, проверьте токен и интернет.
- Если бот сообщает об ошибке `ADMIN_ID`, проверьте положительное число в `.env` и перезапустите бота. Если обращения не доставляются, проверьте ID и что администратор начал личный чат с ботом.
- Если настройки не загружаются, проверьте, что активировано Python-окружение, доступна команда `python` и у процесса есть права на запись в папку проекта. После исправления перезапустите бота.
- Если при `npm run build` не найдены пакеты, выполните `npm install` в папке проекта. Если `node`, `python` или `javac` не распознаются, проверьте их установку и PATH, затем откройте новый терминал.

Не публикуйте `.env` или базу данных: они перечислены в `.gitignore`. Команды для Mini App и его конфигурация относятся к прежнему этапу, а не к запуску нового бота.
