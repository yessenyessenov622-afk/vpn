# Подготовка переноса бота на первый сервер

Перенос выполнен на первый сервер. Служба `telegram-vpn-bot` включена;
сквозная проверка через Telegram ещё требуется. Серверный и локальный экземпляры
с одним токеном не должны работать одновременно.

1. Перед переносом проверить состояние ограниченного контроллера и действующий
   публичный IP в `/etc/telegram-vpn-controller/endpoint`. Не изменять работающий
   peer и другие серверы.
2. Установить на первом сервере Node.js, npm и Python, создать отдельную
   системную учётную запись `telegram-vpn-bot`. Подготовить каталог
   `/opt/telegram-vpn-bot` с исходниками и сборкой без пользовательских данных;
   подготовить Python-окружение `.venv` и установить зависимости.
3. Настройки хранятся в `/opt/telegram-vpn-bot/.env` с правами 0600; их читает
   служба через dotenv. Данные переданы в зашифрованном пакете без вывода в
   команды, журналы и GitHub.
4. Остановить локального бота (`Ctrl+C` в окне, где запущен `npm start`),
   дождаться завершения процесса Python. Снять резервную копию `users.sqlite3`
   с помощью SQLite backup API, проверить её `PRAGMA integrity_check` и
   сохранить оригинал. Не пересоздавать базу.
5. Проверить, нет ли уже нужных данных на сервере. Если есть, не перезаписывать:
   сначала установить происхождение данных и согласовать объединение. Передать
   проверенную копию базы по защищённому каналу в `/opt/telegram-vpn-bot/` с
   ограниченными правами. Проверить целостность, число записей и подписки,
   не печатая персональные данные.
6. После проверки установить шаблон `telegram-vpn-bot.service`, проверить
   `systemd-analyze verify`, включить и запустить службу. Проверить состояние,
   затем убедиться через Telegram, что работает только серверный экземпляр.
   При откате сначала остановить серверную службу и только затем запускать
   локального бота; не заменять серверную базу старой копией без сверки.

Служба установлена и запущена на первом сервере. Автоматическая сверка запускается
при старте и повторяется примерно раз в минуту; при сбоях требуется повторная
сверка, а задержка отзыва может увеличиться. Для возврата на Windows
сначала отключите и остановите серверную службу и перенесите обратно актуальную
серверную базу: старая локальная копия не содержит последующие изменения.
